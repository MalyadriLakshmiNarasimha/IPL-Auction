# Project Audit Report — IPL + PKL Sports Auction

**Audit Date:** 2026-11-26  
**Scope:** Full-stack inspection of `src/`, `server/`, `prisma/`, `scripts/`, `package.json`, configuration files, API routes, Socket.IO handlers, authentication/session logic, database models, and IPL/PKL auction engines.

---

## Executive Summary

Baseline verification (`npx tsc --noEmit`, `npm run lint`, `npm run test`, Playwright E2E browser testing, and live MySQL database inspection) revealed **20 distinct issues** across frontend React components, Socket.IO synchronization, IPL/PKL rule separation, My Rooms & History isolation, database persistence, TypeScript types, API auth gating, and security hardening. All 20 issues have been fixed and verified.

---

## Identified Issues & Repair Strategy

| # | Severity | Category | Affected File(s) | Root Cause | Repair Strategy |
|---|---|---|---|---|---|
| 1 | **Critical** | React Runtime / TypeScript | `src/components/GavelOverlay.tsx` | Uses `useCallback` on line 34 without importing it from `'react'`, causing `TS2304` and a client `ReferenceError` whenever SOLD/UNSOLD overlay mounts. Inner `setTimeout` is also uncleaned on unmount, and missing `key` prop in parent prevents `isDismissed` reset across consecutive players. | Import `useCallback`, clean up inner `setTimeout` on unmount, reset `isDismissed` on `player?.id`/`phase` change, and pass explicit `key` in `src/app/room/[code]/page.tsx`. |
| 2 | **Critical** | Auction Flow / Freezing | `src/app/room/[code]/page.tsx`, `server/room.ts` | When Round 1 ends with unsold players, `server/room.ts` sets `stage = 'unsold_auction'` and runs Round 2 `announcing`/`bidding` phases, but `room/[code]/page.tsx` only renders the live bidding UI for `currentStage === 'main_auction' \|\| 'lobby'`, trapping users in `UnsoldAuctionBoard` without bidding controls. Also `UnsoldAuctionBoard` `onReEnter` redundantly emits `stage_change` after `unsold_pool_configure`. | Render live auction scoreboard for `unsold_auction` during active auction phases (`starting`, `announcing`, `bidding`, `sold`, `unsold`, `paused`), and show `UnsoldAuctionBoard` only during `unsold_round`/`round_break`. Remove redundant `handleTransitionStage` call in `onReEnter`. |
| 3 | **Critical** | Socket.IO Memory Leak / Duplicate Listeners | `src/app/room/[code]/page.tsx` | `useEffect` registers 24 socket listeners (`connect`, `connect_error`, `disconnect`, `pass_updated`, `withdraw_success`, etc.) using inline anonymous functions, and cleanup omits 5 events and calls `socket.off(event)` without handler references. Also `handleConfirmExit` leaves voice commentary and several listeners attached. | Store named handler callbacks and remove all 24 exact handler references in `useEffect` cleanup; cancel voice commentary and timers on exit. |
| 4 | **High** | Database / Silent In-Memory Fallback | `src/lib/db.ts` | `roomParticipant.upsert` and `commentaryLog.create` catch Prisma errors even when `mysqlOk === true` and silently fall through to in-memory Maps (`memParticipants`, `memCommentary`) outside test mode, risking silent data loss. | Enforce `process.env.NODE_ENV === 'test'` guard before any in-memory fallback in `roomParticipant` and `commentaryLog`; surface/log real DB errors in dev/prod. |
| 5 | **High** | Database Race Condition / FK Violations | `server/index.ts`, `server/room.ts` | `POST /api/rooms` calls `roomManager.createRoom()` (which triggers `addCommentary` -> `db.commentaryLog.create`) *before* `await db.room.create()`, causing MySQL foreign key violations (`room_code`) on creation and missing initial `RoomSnapshot`/`RoomParticipant` records if user hasn't joined via socket yet. | Create `db.room` record first (or ensure existence) before persisting commentary/participants, and create initial snapshot/host participant entry cleanly. |
| 6 | **High** | Bid Sequence Collision & History Cap | `server/room.ts` | `placeBid` computes `bidSeq = room.auction_state.bids.length`, which is capped at 10 (`if (bids.length > 10) bids.pop()`). Bids 11+ collide on `bid_events` unique constraint `[room_code, player_id, bid_sequence]` and under-report `bids_count`. | Track monotonic `current_player_bid_count` per player in `RoomRecord` and reset on `nextPlayer`. |
| 7 | **High** | PKL Auction Logic & Rules | `server/room.ts`, `src/app/room/[code]/page.tsx`, `src/components/PlayingXILeaderboardView.tsx` | `startAuction` passes `ALL_PLAYERS.length` (274) instead of `sourcePool.length` (235 for PKL); `respondTrade` counter-player lookup uses `getPlayerById` only (fails for PKL `k-xxx`); `submitPlayingXI` hardcodes 11 players and max 4 overseas (rejecting PKL 7-player / max 2 overseas lineups); `room/[code]/page.tsx` hardcodes `274` in pool display and start validation. | Branch cleanly on `sport_type === 'PKL'` across `startAuction`, `respondTrade`, `submitPlayingXI`, `restoreRoomFromSnapshot`, `server/index.ts` DB hydration, and UI pool/lineup labels. |
| 8 | **High** | Stage Evaluation & Results Lifecycle | `server/room.ts` | Transitioning to `squad_evaluation` never populates `room.results`, leaving `SquadEvaluationView` empty; transitioning to `playing_xi_evaluation` immediately calls `completeAuction`, skipping `PlayingXILeaderboardView`. | Compute and attach preliminary `room.results` during `squad_evaluation` and `playing_xi_evaluation` without prematurely marking the room `completed`. |
| 9 | **High** | My Rooms & History Separation | `src/app/api/my-rooms/route.ts`, `src/app/api/history/route.ts`, `src/app/my-rooms/page.tsx`, `src/app/history/page.tsx`, `server/db/index.ts` | `abandoned` rooms are not excluded from `/api/my-rooms` or `/api/history`; `loadAllActiveRoomCodes` restores all stale/test non-completed rooms on server boot; `My Rooms` lacks a user action to leave/archive rooms; `History` defaults to showing `Ongoing Auctions` rather than focusing on completed/archived auctions; participant count can drift between `r.participants` and snapshot `participants`. | Filter out `abandoned`/`cancelled`/`archived` and unassociated test rooms; provide room leave/archive endpoint & UI in My Rooms; separate History view cleanly to focus on completed/archived auctions; deduplicate participant counts; limit server boot restoration to recent genuine active rooms. |
| 10 | **High** | Security / Auth Bypass | `server/index.ts` | Hardcoded production `SESSION_SECRET` fallback in `server/index.ts` (lines 34, 894); `POST /api/rooms` (`isBotTest`) and Socket.IO middleware (`bot_token_` / `isBotTest`) allow unauthenticated access in production if spoofed. | Remove hardcoded production secret fallback; restrict `isBotTest`/`bot_token_` bypasses strictly to `NODE_ENV === 'test'` (or explicit non-production `ALLOW_BOT_SIMULATION` flag). |

| 12 | **Medium** | Room Hydration & Snapshot Consistency | `src/app/api/rooms/route.ts`, `server/index.ts`, `server/room.ts` | Next.js fallback snapshot uses mismatched fields (`total_spent`, `Batsman`, missing `stage`/`bids`); `server/index.ts` omits `sport_type` when creating room from DB fallback; `restoreRoomFromSnapshot` relies on `code.startsWith('K')` instead of `settings.sport_type === 'PKL'`; `all` results routes have inconsistent fallback URLs. | Align Next.js snapshot payload with `RoomManager.createRoom`, pass `dbRoom.sport_type` during hydration, prioritize `settings.sport_type`, and standardize internal backend URL resolution. |
